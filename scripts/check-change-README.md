# check-change.sh — μηχανικοί έλεγχοι πριν το push, χωρίς μοντέλο (DRAFT, βήμα 4 — 22/9/2026)

**Τι είναι:** ένα shell script που τρέχει ΤΟΠΙΚΑ πριν το push (`scripts/check-change.sh [BASE] [HEAD]`, προεπιλογή `origin/main HEAD` = όλο το push) και τυπώνει μία γραμμή ανά έλεγχο: `[ΠΡΑΣΙΝΟ|ΚΟΚΚΙΝΟ|ΓΚΡΙ] Μx — κάλυψη: τι εξέτασε — λεπτομέρειες`. Exit 0 πράσινο · 1 κόκκινο (μην κάνεις push) · 2 γκρι (εκτός κάλυψης ή ληγμένο → ρόλος 1 ή άνθρωπος, `docs/grok-bot/07-change-review-runbook.md`). **ΔΕΝ είναι σε git hook ούτε CI** — ο owner αποφασίζει.

**Δύο κανόνες (owner 22/9):** (1) **Ένας έλεγχος που δεν ξέρει κάτι λέει ΓΚΡΙ, όχι πράσινο** — νέο module εκτός `app.html`, νέο πρόθεμα διαδρομής, νέος `*_PERMS`, νέος πίνακας χωρίς αντιστοιχία στον Worker, αρχείο εκτός γνωστών φακέλων. (2) **Κάθε 14 ημέρες μία ώρα αναθεώρησης της λίστας** — το script το θυμίζει μόνο του (Μ11 από τη σταθερά `REVIEWED`, Μ10 από ετικέτες `[επαλ. YYYY-MM-DD]` στο `skill-tms-knowledge.md` — **δεν υπάρχουν ακόμη**, γι' αυτό το Μ10 βγαίνει ΓΚΡΙ σήμερα).

**Τίποτα hardcoded:** modules/core από τα `<script src>` του `app.html`, `*_PERMS` από `const|var \w*PERM\w*`, κλειδιά χάρτη από τα `Label: "column"` του Worker, προθέματα διαδρομών από τα `url.pathname` του BASE. Δεν αγγίζει το working tree (`git show`)· εκτελεί μόνο `node --check` σε προσωρινά αντίγραφα.
