# admin — Settings · Trash · Error Log

`core/router.js:305-315` + `core/utils.js` (inline renderers) · perm
`settings` (owner + management) — **εκτός από το Error Log, που δεν έχει gate**
**ελέγχθηκαν και τα τρία live**

---

## 1. ΣΕ ΤΙ ΧΡΗΣΙΜΕΥΟΥΝ

- **Settings** — παραμετροποίηση. Δεν υπάρχει (placeholder).
- **Trash** — ανάκτηση διαγραμμένων. Job-to-be-done: _«σβήστηκε κατά λάθος,
  φέρ' το πίσω»_. Χρήση: σπάνια, αλλά τη στιγμή που χρειάζεται είναι κρίσιμο.
- **Error Log** — τι έσπασε στον browser του χρήστη. Χρήστης: ο owner όταν
  κάποιος πει «δεν δουλεύει».

**Αν αποτύχουν**: μια λάθος διαγραφή γίνεται μόνιμη· ένα σφάλμα που βλέπει
καθημερινά ο dispatcher δεν φτάνει ποτέ σε αυτόν που μπορεί να το φτιάξει.

## 2. ΤΙ ΒΛΕΠΕΙ ΣΗΜΕΡΑ Ο ΧΡΗΣΤΗΣ

- **Settings:** placeholder «This module is under development» (614px).
- **Trash:** «0 deleted record(s) — **last 50 kept in browser storage**» +
  «Trash is empty / Deleted records will appear here for recovery» (614px).
- **Error Log:** «5 entries total · 5 shown · **Sentry ON**», κουμπιά
  JSON/CSV/Clear, τρεις κάρτες (CRITICAL 0 · WARNING 5 · INFO 0), τρία φίλτρα
  (Severity/User/Time) και πίνακας 6 στηλών με πραγματικά σφάλματα (678px).

## 5. ΠΡΟΤΑΣΕΙΣ

**Π1 — Μην ισχυρίζεσαι «Sentry ON» χωρίς DSN.**
_ΓΙΑΤΙ:_ AD-1. _ΠΩΣ:_ ο δείκτης διαβάζει `TMS_SENTRY_DSN` και δείχνει
«**Κεντρική καταγραφή: ΑΝΕΝΕΡΓΗ** — τα σφάλματα μένουν μόνο σε αυτόν τον
browser» σε `var(--warning)` όταν είναι κενό. _ΚΟΠΟΣ:_ **S (μία γραμμή)**.
_ΡΙΣΚΟ:_ κανένα. Το ουσιαστικό fix είναι να μπει το DSN (ανοιχτό P0 από 3/8).

**Π2 — Πες την αλήθεια για το Trash.** _ΓΙΑΤΙ:_ AD-2. _ΠΩΣ:_ μέχρι να γίνει
server-side, το empty state γράφει: «Ο κάδος κρατά τις τελευταίες 50
διαγραφές **μόνο σε αυτόν τον υπολογιστή**. Διαγραφές άλλων χρηστών δεν
εμφανίζονται εδώ.» — και το ίδιο κείμενο εμφανίζεται στο modal επιβεβαίωσης
**κάθε διαγραφής**, ώστε ο χρήστης να ξέρει τι ρισκάρει τη στιγμή που
διαγράφει. _ΚΟΠΟΣ:_ S. _ΡΙΣΚΟ:_ κανένα.

**Π3 — Βάλε gate στο Error Log.** _ΓΙΑΤΙ:_ AD-3. _ΠΩΣ:_ `core/router.js:313`
→ `if (can('settings') !== 'full') { c.innerHTML = showAccessDenied(); break; }`
όπως ήδη κάνουν τα διπλανά routes. _ΚΟΠΟΣ:_ S. _ΡΙΣΚΟ:_ οι dispatchers χάνουν
πρόσβαση — σωστό, αλλά ανακοινώστε το.

**Π4 — «Clear» με εξαγωγή-πρώτα.** _ΓΙΑΤΙ:_ AD-5. _ΠΩΣ:_ `confirmAction(
'Θα διαγραφούν 5 καταγραφές. Θέλεις να τις κατεβάσεις πρώτα;',
{confirmLabel:'Διαγραφή', danger:true})` με κουμπί «Λήψη JSON» μέσα στο modal.
_ΚΟΠΟΣ:_ S. _ΡΙΣΚΟ:_ κανένα.

**Π5 — Τι πρέπει να δείχνει το Settings όταν φτιαχτεί.**
_ΠΩΣ:_ **όχι** γενικές ρυθμίσεις. Τρία μόνο πράγματα που σήμερα ζουν σε
κώδικα ή σε localStorage και κοστίζουν deploy για να αλλάξουν:
(1) **Ρόλοι & χρήστες** — ποιος βλέπει τι (σήμερα σε `config.js:308-340`,
τρία αντίγραφα εκτός συγχρονισμού)· (2) **Όρια & κατώφλια** — ημέρες
προειδοποίησης λήξης, όριο παλετών ανά φορτηγό, στόχοι KPI (σήμερα
hardcoded)· (3) **Κατάσταση συστήματος** — DSN, έκδοση, τελευταίο backup,
συνδεδεμένο backend. Το placeholder σήμερα πρέπει να λέει ακριβώς αυτά
(βλ. `payroll.md` Π1). _ΚΟΠΟΣ:_ L. _ΡΙΣΚΟ:_ οι ρόλοι είναι client-side —
ένα UI ρόλων χωρίς server-side RBAC δίνει ψευδή αίσθηση ελέγχου.

**Π6 — Συγχώνευσε τα διαγνωστικά σε μία σελίδα με καρτέλες.**
_ΓΙΑΤΙ:_ AD-7. _ΠΩΣ:_ μία εγγραφή «Διαγνωστικά» με καρτέλες
`Σφάλματα · Ίχνος αλλαγών · Έλεγχος μετρήσεων · Κάδος`. Το ADMIN πέφτει από
5 σε 2 εγγραφές. _ΚΟΠΟΣ:_ M. _ΡΙΣΚΟ:_ κρατήστε τα παλιά routes ως redirects.

## 9. ΤΙ ΔΕΝ ΠΡΕΠΕΙ ΝΑ ΑΛΛΑΞΕΙ

- **Ότι το Error Log υπάρχει καθόλου.** Ελάχιστα εσωτερικά εργαλεία αυτού του
  μεγέθους έχουν ορατό log σφαλμάτων με φίλτρα και εξαγωγή. Χρειάζεται μόνο
  να λέει την αλήθεια (Π1) και να προστατεύεται (Π3).
- **Οι τρεις κατηγορίες σοβαρότητας με τα παραδείγματά τους** («auth,
  network, 4xx» / «aborts, expected») — εξηγούν τι σημαίνει η κατηγορία.
- **Η εξαγωγή σε JSON και CSV** — το JSON πάει σε προγραμματιστή, το CSV σε
  υπολογιστικό φύλλο.
- **Το ότι το Trash λέει ρητά «last 50»** — τουλάχιστον δηλώνει το όριο.
