# Κατάλογος περιπτώσεων για το απόλυτο sync v6 (r7)

Κάθε γραμμή είναι περίπτωση του τεστ (PLAN §Γ2). Ο κατάλογος ακολουθεί το PLAN r7. Όπου διαφωνούν, λάθος έχει ο κατάλογος, και διορθώνεται πριν γραφτεί το τεστ.

**Σύμβολα:**
- `E` = εξαγωγή, `I` = εισαγωγή, `G` = μέλος ομάδας, `R` = ρότα, `L1` / `L2` = σκέλη σπασμένης παραγγελίας·
- `T1` / `T2` = φορτηγά, `D1` / `D2` = οδηγοί, `P1` / `P2` = συνεργάτες·
- `Ρ`, `Ρ'` = δρομολόγια του S0, που κρατούν τον κωδικό τους στη σύγκριση.

**Ενέργειες:**
- `assign` / `unassign` / `match` / `unmatch` / `join` / `leave` / `dissolve` / `rota+` / `rota-` / `split` / `rejoin` / `reorder` / `restore` / `absorb` / `keep_sep` = οι RPC μίας κίνησης (PLAN §Β2)·
- `form:x` = απλή PATCH από φόρμα / Daily Ops / παλιά καρτέλα·
- `drain` = εκκένωση ουράς.

**Πότε ισχύει:** όπου δεν γράφεται αλλιώς, η τελική κατάσταση είναι σε `act`. Οι ενέργειες αφήνουν στις παραγγελίες την ίδια τελική κατάσταση με σήμερα (PLAN §Β2, «Συμπεριφορά»)· αλλάζει μόνο ποιος βάζει το δρομολόγιο. Όπου μια γραμμή γράφει «με «ναι» στο Nx», ισχύει μόνο αν ο owner το εγκρίνει, από τη Φάση 3α.

**«Σειρά: όλες»** = κάθε μετάθεση των ενεργειών, με drain μετά από κάθε βήμα **και** μόνο στο τέλος. Η **σύνθεση** των δρομολογίων πρέπει να βγαίνει ίδια. Ο κωδικός δρομολογίου χωρίς χρήματα μπορεί να διαφέρει (PLAN Γ1).

**Κανόνας:**
- Q1–Q8 όπως απαντήθηκαν 4/10 (χωρίς εξαίρεση Status)· N0, N2–N9, N12, N14, N16 (PLAN Α§4)·
- PLAN §Β2 / §Β3.n, όπου n = το βήμα του `rt_family_desired`:
  - 1 εκτελέσιμα, 3 υποψήφια, 4 επιλογή, 5 αναμονή, 6 σβησμένη, 7 περισσευούμενο, 8 πύλες, 10 όχημα / οδηγός, 11 ημερομηνίες·
- §Β4 0.x.
