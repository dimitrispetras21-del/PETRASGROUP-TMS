## Βήμα 6 — E-30: Επίπεδο Α
1. `049_req_id.sql`. Επιβεβαίωση: 3 στήλες (SELECT στο τέλος του αρχείου).
2. Deploy Worker με τη διαδικασία του CLAUDE.md:
   - φρουρός των τριών πριν και μετά·
   - αντίγραφο του bundle·
   - bindings.
   **Η πρώτη γραμμή `{"kind":"req",…}` στα Workers Logs είναι η απόδειξη** ότι τα `console.*` φτάνουν (22/9: 0 γραμμές σε 24h).
3. Push του front: `core/api.js`, `core/utils.js`, `core/pallet-feed.js`, `core/share-helpers.js`, `modules/costs.js`,
   `modules/audit_trail.js`, `modules/locations.js`, `modules/weekly_intl.js`, `app.html` (`?v=`), `sw.js` (`SW_VERSION`).

**Όρος rollback (αξιολόγηση Β 23/9):** αν ποτέ γίνει επαναφορά του Worker, **η γραμμή CORS
`Access-Control-Allow-Headers: …, x-tms-req, x-tms-app` δεν αφαιρείται ποτέ** — ούτε σε παλιό bundle. Είναι
αβλαβής για παλιό κώδικα και προστατεύει όσα tabs έχουν ήδη μάθει το Επίπεδο Α. (Ο front δέχεται την ανακοίνωση
μόνο με φρέσκια χρονοσφραγίδα ±10′, άρα απάντηση από cache δεν την ανάβει — αλλά ένα ανοιχτό tab τη θυμάται.)
```sql
SELECT count(*) FILTER (WHERE req_id IS NOT NULL) AS me_req, count(*) AS synolo
  FROM audit_log WHERE created_at > now() - interval '1 hour';   -- me_req > 0 μετά την πρώτη ενέργεια χρήστη
```
