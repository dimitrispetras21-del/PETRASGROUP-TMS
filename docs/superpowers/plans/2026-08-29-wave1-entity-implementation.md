# Κύμα 1 — υλοποίηση της μονάδας `core/entity.js`

> **Πέρασμα σε καθαρή συνεδρία.** Ό,τι χρειάζεται είναι γραμμένο· μη ρωτήσεις
> τον owner πράγματα που απαντιούνται εδώ ή στα αρχεία που δείχνει.

**Στόχος:** να υλοποιηθούν στον κώδικα οι 21 οθόνες που σχεδιάστηκαν 29/8, χωρίς
να χαθεί κανένα πεδίο και χωρίς να σπάσει καμία από τις έξι ζωντανές οθόνες.

**Ρίσκο:** το `core/entity.js` σερβίρει **έξι σελίδες σε καθημερινή παραγωγική
χρήση** (clients, partners, drivers, trucks, trailers, workshops). Η ομάδα
δουλεύει 05:30–14:30.

## 1. Σκληροί περιορισμοί

- **Βαθμίδα 1 → σκληρή πύλη.** Κανένα από τα 24 πεδία του συμβολαίου δεν φεύγει.
- **Γραμμή ≤40px, ≥20 ορατές** στα 1080p. Το 44 είναι οροφή, όχι στόχος — στα 44
  χωρούν 18 και ο κανόνας #5 σπάει.
- **Καμία κοπή** σε επωνυμία ή τοποθεσία (κανόνας #6). Μηδέν
  `truncate`/`ellipsis`/`line-clamp`.
- **Κανένα ωμό hex** στο module (κανόνας #1). Χρησιμοποίησε τα tokens που
  προστέθηκαν 28/8 στο `:root` — `--chip-own`, `--badge-*`, `--border-row`,
  `--text-inverse`, `--bg-row-alt`, `--accent-text` κ.λπ.
- **Άγνωστο ≠ μηδέν** (κανόνας #3). Τα τρία νεκρά πεδία εμφανίζονται `—`.
- **Ο dispatcher δεν βλέπει ποτέ P&L.** Η καρτέλα πελάτη δείχνει όγκο και
  συχνότητα, όχι έσοδα ή περιθώριο (κλείδωμα owner 23/8).
- **Supabase = SELECT μόνο.** Καμία migration χωρίς ρητή έγκριση του Δημήτρη.
- **Deploy μετά τις 15:00**, μία μονάδα τη φορά (αρχή 7).
- Μετά από κάθε αλλαγή αρχείου: `bash scripts/bump-versions.sh` + commit + push.

## 2. Εκκρεμείς αποφάσεις owner

1. **Τα τρία νεκρά πεδία** — `contact_person` (πελάτες, συνεργάτες),
   `payment_terms_days` (πελάτες), μισθός (οδηγοί). Στήλες στη βάση ή αφαίρεση
   από τις οθόνες; **Μέχρι να αποφασιστεί:** υλοποίησε το σχεδιασμένο —
   απενεργοποιημένο πεδίο με αιτία «Δεν αποθηκεύεται — εκκρεμεί στήλη στη βάση»,
   και `—` στη στήλη.
2. **Ανασκόπηση των 21 οθονών** στο Figma. Αν δεν έχει γίνει, ρώτησε πριν
   γράψεις κώδικα για μια οθόνη.

## 3. Σειρά εργασίας

Μία οθόνη τη φορά, με τους κριτές ανάμεσα. Πρώτα η **λίστα**, μετά η **καρτέλα**,
μετά η **φόρμα** — και ξεκίνα από τα **trucks**, που είναι το πληρέστερα
σχεδιασμένο και το λιγότερο επικίνδυνο.

Για κάθε βήμα:
1. Διάβασε τη σχεδίαση από το Figma (`get_design_context` στο σχετικό frame)
2. Γράψε τον κώδικα στο `core/entity.js`
3. `npm run critics` — πρέπει να μείνει **12/12 μονάδες** και οι ζωντανοί έλεγχοι
   να μην χειροτερέψουν
4. `bash scripts/bump-versions.sh` → commit → push

## 4. Ο κριτής είναι ήδη εκεί

`npm run critics` τρέχει: συμβόλαιο, ρόλοι, tokens, κοπή, άγνωστο≠μηδέν,
ζωντανό, και τον δεσμό Figma↔κώδικα. Σημερινή βάση, **πριν** αγγίξεις τίποτα:

```
12/12 μονάδες εντός ορίων
✓ figma ↔ κώδικας: 8 συναρτήσεις επαληθεύτηκαν
31/33 ζωντανοί έλεγχοι πέρασαν · 2 γνωστό κενό   (exit 1)
```

Τα 2 είναι τα `weekly_intl`/`weekly_natl` χωρίς συμβόλαιο — **γνωστό κενό, όχι
δική σου δουλειά**. Αν εμφανιστεί τρίτο, το έσπασες εσύ.

⚠️ Οι ζωντανοί έλεγχοι τρέχουν στο **deployed** GitHub Pages, όχι στο τοπικό σου
αρχείο. Για να δεις τη δική σου αλλαγή, τρέξε τα με `PW_BASE_URL` σε τοπικό
server, αλλιώς επαληθεύεις τον παλιό κώδικα.

## 5. Ορισμός του «τελείωσε»

1. Και οι έξι οθόνες αποδίδονται κατά τη σχεδίαση
2. `npm run critics`: 12/12 στατικά, κανένας **νέος** ζωντανός έλεγχος κόκκινος
3. Το συμβόλαιο `entity.json` περνάει ως **σκληρή πύλη** — μηδέν χαμένα πεδία
4. Μετρημένο: ≥20 γραμμές στα 1080p, μηδέν κομμένες επωνυμίες
5. `docs/redesign/OBSERVATIONS.md` ενημερωμένο με ό,τι πήγε στραβά
6. Merge μετά τις 15:00
