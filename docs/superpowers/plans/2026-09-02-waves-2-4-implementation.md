# Υλοποίηση κυμάτων 2-4 — το σχέδιο

**Ημερομηνία:** 2/9/2026 · **Κατάσταση:** έτοιμο προς εκκίνηση
**Προϋποθέσεις που έκλεισαν:** έλεγχος συνέπειας 2/9 (φιλοσοφία τηρείται και
στα τρία κύματα) · re-capture συμβολαίων · τρεις αποφάσεις owner (DECISION_LOG 2/9)

---

## 1. Τρεις αρχές που δεν αλλάζουν

1. **Μία μονάδα = ένα worktree = ένας agent.** Μηδέν επικάλυψη αρχείων
   ανάμεσα στις 12 μονάδες (μετρημένο 2/9: 15 αρχεία, κανένα σε >1 μονάδα).
   Ο κανόνας του ενός καναλιού ισχύει *ανά έδαφος*· τα εδάφη γίνονται πολλά.
2. **Ο agent αγγίζει ΜΟΝΟ τα αρχεία της μονάδας του.** Ό,τι κοινό — tokens,
   `app.html`, `sw.js`, baselines, `DECISION_LOG`, `OBSERVATIONS` — **δεν το
   γράφει, το ζητάει** στο παραδοτέο του. Ένας ολοκληρωτής τα γράφει μία φορά.
3. **Επαλήθευση ανά μονάδα μέσα στο worktree, πλήρης σουίτα μία φορά στο
   merge.** `npx playwright test tests/critics/ -g "<unit>"` ≈ 1 λεπτό.
   `npm run critics` ≈ 10 λεπτά, από τον ολοκληρωτή, μετά από κάθε merge.

## 2. Οι παρτίδες — με σειρά ρίσκου

| # | Μονάδες | Αρχεία | Γιατί μαζί |
|---|---|---|---|
| **1** | `audit` · `locations` · `pallets` | 6 | χαμηλό ρίσκο, μικρά αρχεία — **βαθμονομεί τη διαδικασία** |
| **2** | `maintenance` · `dashboard` · `daily_ops` | 3 | μεσαίο· το maintenance έχει 6 οθόνες σε 1 αρχείο |
| **3** | `weekly_intl` · `weekly_natl` · `orders_intl` · `orders_natl` | 4 | **υψηλό** — καθημερινή χρήση, kanban, χωρίς συμβόλαιο |

**Η 2η δεν ξεκινά πριν η 1η γίνει merge ΚΑΙ deploy.** Ό,τι μάθουμε στην 1η
(σύγκρουση tokens, λάθος στο prompt, χρόνος επαλήθευσης) διορθώνει το prompt
της 2ης. Τρεις με τέσσερις agents ταυτόχρονα — όχι δέκα: ο περιορισμός είναι
πόσα παραδοτέα μπορεί να κρίνει ο owner, όχι η μηχανή.

## 3. Ο κύκλος κάθε agent

```
1. git worktree add ../tms-<unit> -b impl/<unit>
2. Διάβασε, με αυτή τη σειρά:
     docs/DECISION_LOG.md (2/9 — οι τρεις αποφάσεις)
     docs/redesign/OBSERVATIONS.md
     docs/redesign/contracts/<unit>.json   ← τι ΔΕΝ επιτρέπεται να χαθεί
     τα frames του Figma για τη μονάδα (get_design_context)
     τα αρχεία της μονάδας — ο υπάρχων κώδικας
3. Υλοποίησε ΜΟΝΟ στα αρχεία της μονάδας. Νέο token; χρησιμοποίησε το
   πλησιέστερο υπάρχον και ΖΗΤΗΣΕ το σωστό στο παραδοτέο.
4. Τοπικός server σε ΔΙΚΟ ΣΟΥ port. PW_BASE_URL=http://localhost:<port>/
   npx playwright test tests/critics/ -g "<unit>"  → πράσινο.
   ⚠ Χωρίς PW_BASE_URL οι ζωντανοί κριτές χτυπούν το deployed Pages και
   επαληθεύουν ΤΟΝ ΛΑΘΟΣ ΚΩΔΙΚΑ. Έγινε στις 29/8 πριν το merge του κύματος 1.
5. Παραδοτέο: το branch + αναφορά με
     · tokens που ζήτησες (όνομα, τιμή, γιατί)
     · αποφάσεις που χρειάζονται τον owner
     · ΤΙ ΔΕΝ ΜΠΟΡΕΣΕΣ ΝΑ ΕΠΑΛΗΘΕΥΣΕΙΣ — ρητά
```

## 4. Ο κύκλος του ολοκληρωτή (ένα κανάλι)

```
1. Μάζεψε τα αιτήματα tokens όλης της παρτίδας → πρόσθεσέ τα ΜΙΑ φορά στο style.css
2. Ανά branch, με σειρά ρίσκου:
     git merge --no-ff impl/<unit>        ← ένα revert = ένα merge
     npm run critics                      ← πλήρης σουίτα, 12/12 · 42/44 · 2 γνωστά
     αν κόκκινο: git revert -m 1, πίσω στον agent — οι άλλες μονάδες ανέπαφες
3. bump-versions.sh ΜΙΑ φορά στο τέλος της παρτίδας
4. Deploy εκτός ωρών (η ομάδα 05:30-14:30)· smoke στο live από τον owner
5. Καταγραφή: DECISION_LOG (αποφάσεις) · OBSERVATIONS (τι πήγε στραβά)
```

## 5. Ρόλοι

| Ποιος | Κάνει |
|---|---|
| **Agents** (Fable 5.1, ένας ανά μονάδα) | υλοποίηση στα δικά τους αρχεία, επαλήθευση μονάδας, αναφορά |
| **Ολοκληρωτής** (αυτή η συνεδρία) | tokens, merge, πλήρης σουίτα, bump, καταγραφή |
| **Owner** | αποφάσεις που ζητούν οι agents · smoke στο live μετά από deploy · deploys του Worker |

## 6. Τι ισχύει από τις αποφάσεις της 2/9 — για ΟΛΟΥΣ τους agents

- **Κατάσταση:** κάθε οθόνη κρατά το δικό της ιδίωμα. Ημερήσιο = κείμενο,
  λίστες = κουκκίδα+λέξη, ισοζύγιο = pill, weekly = pills own/partner.
- **`loaded_at`: ΟΧΙ.** Το ημερήσιο δείχνει ΜΟΝΟ τη λέξη της κατάστασης, όχι
  ώρα/όνομα — παρότι το frame τα δείχνει. ΜΗΝ τα διαβάσεις από το audit_log.
- **`metrics_audit`: εκτός.** Η μονάδα `audit` υλοποιεί μόνο το `audit_trail`.
- **Δικαιώματα: ΔΕΝ σχεδιάζεις/υλοποιείς γύρω από τον dispatcher** (owner
  30/8). Σφίγγουν στο τέλος, σε μία φάση.

## 7. Γνωστά κενά που ΔΕΝ μπλοκάρουν — γραμμένα για να μη ξαναβρεθούν

| Κενό | Κατάσταση |
|---|---|
| Τα weekly δεν έχουν συμβόλαιο (kanban) | το `w4-kanban-contract` του Figma ορίζει τι θα μετρά ο κριτής· γίνεται κώδικας ΜΕΤΑ την 3η παρτίδα |
| Στήλες Ιστορικού Φορτηγών/Ρυμουλκών εκτός σκληρής πύλης | πίνακας μόνο μετά από επιλογή οχήματος· ο εξαγωγέας πρέπει να επιλέγει |
| Ο εξαγωγέας διαβάζει κέλυφος/τιμές ως ενέργειες | θόρυβος στα `actions`, δεν αγγίζει την πύλη πεδίων |
| `estimated_cost` δεν αποθηκεύεται | ίδια περίπτωση με `contact_person`· μία γραμμή στον Worker, με το επόμενο deploy |
| 10 οθόνες χωρίς κύμα (5 εξαιρέσεις + 5 ατεκμηρίωτες) | απόφαση owner: μένουν εκτός προς το παρόν |

## 8. Ορισμός του «τελείωσε»

**Ανά μονάδα:** οι κριτές της μονάδας πράσινοι στο worktree · το συμβόλαιο
δεν έχασε πεδίο · η αναφορά έχει και τα τρία (tokens, αποφάσεις, μη
επαληθευμένα).
**Ανά παρτίδα:** όλα merged · `npm run critics` 12/12 · 42/44 · 2 γνωστά ·
deployed · smoke owner · DECISION_LOG + OBSERVATIONS ενημερωμένα.
**Συνολικά:** 16 διαδρομές σε παραγωγή, κανένα κόκκινο νέο, ο κριτής kanban
γραμμένος.

## 9. Τι μπορεί να πάει στραβά — και τι κάνουμε

| Κίνδυνος | Αντίμετρο |
|---|---|
| Δύο agents ζητούν το ίδιο token με άλλη τιμή | ο ολοκληρωτής αποφασίζει ΜΙΑ τιμή, το γράφει στο DECISION_LOG |
| Agent αγγίζει `style.css` παρά τον κανόνα | το merge το δείχνει στο diff· επιστρέφει με «μόνο τα αρχεία σου» |
| Agent επαληθεύει χωρίς PW_BASE_URL | η αναφορά του πρέπει να γράφει το port· χωρίς port = δεν επαληθεύτηκε |
| Το merge σπάει τη σουίτα | `git revert -m 1` — 30 δευτερόλεπτα, οι άλλες μονάδες ανέπαφες |
| Deploy μέσα σε ώρες λειτουργίας | ποτέ· η 1η παρτίδα ανεβαίνει το πρώτο απόγευμα/ΣΚ |
