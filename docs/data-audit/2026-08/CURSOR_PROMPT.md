## ΑΠΟΛΥΤΟΙ ΚΑΝΟΝΕΣ

1. **ΜΗΝ ΑΛΛΑΞΕΙΣ ΟΥΤΕ ΕΝΑ ΑΡΧΕΙΟ.** Κανένα edit, κανένα commit, κανένα
   refactor, καμία «μικρή διόρθωση όσο είμαι εδώ». Μόνο ανάγνωση, και νέα
   αρχεία `.md` μέσα στο `docs/cursor-audit/`.
2. **ΜΗΝ ΙΣΧΥΡΙΣΤΕΙΣ ΤΙΠΟΤΑ ΓΙΑ ΔΕΔΟΜΕΝΑ.** Δεν έχεις πρόσβαση στη βάση,
   στον Worker, ούτε στο `.env.local` — είναι gitignored και δεν υπάρχει στο
   repo σου. Πρόταση της μορφής «Χ εγγραφές είναι λάθος» είναι
   **απαγορευμένη**. Γράφεις μόνο «ο κώδικας θα κάνει Χ», με απόδειξη.
3. **ΚΑΘΕ ΕΥΡΗΜΑ ΘΕΛΕΙ `αρχείο:γραμμή`.** Το grep δίνει ψευδώς θετικά ΚΑΙ

   audit έξι ευρήματα βγήκαν «κλειστά» από αυτόματο matching και ήταν όλα
   ανοιχτά.
4. **ΜΗ ΜΑΝΤΕΨΕΙΣ.** Ό,τι δεν αποδεικνύεται από τον κώδικα πάει στην ενότητα
   «ΑΒΕΒΑΙΑ», όχι στα ευρήματα.

## ΤΙ ΕΙΝΑΙ ΤΟ ΣΥΣΤΗΜΑ

Vanilla JS SPA (χωρίς framework, **χωρίς build step**) → Cloudflare Worker →
Supabase/Postgres. Το `app.html` φορτώνει `config.js`, μετά `core/*.js`, μετά
`modules/*.js` με `?v=TIMESTAMP`. Η σειρά των `<script>` **μετράει**.

**Το κρίσιμο σημείο όλης της αρχιτεκτονικής:** ο Worker
(`worker/src/index.js`, ~3.000 γραμμές) είναι **facade** που μιμείται το API
του Airtable πάνω σε Postgres. Το front end στέλνει **ονόματα πεδίων
Airtable** (π.χ. `'Loading DateTime'`) και ο Worker τα μεταφράζει σε στήλες
Postgres (`loading_datetime`) μέσω χαρτών ανά πίνακα.

**Αν ένα label λείπει από τον χάρτη, χάνεται σιωπηλά.** Δες
`fieldsToColumns()` στο `worker/src/index.js`:

```js
const column = cfg.fields[label] || (cfg.aliases || {})[label];
if (column) row[column] = value;      // ΔΕΝ υπάρχει else
```

# ΕΡΓΑΣΙΑ 1 — Ο ΠΛΗΡΗΣ ΧΑΡΤΗΣ ΠΕΔΙΩΝ *(η σημαντικότερη)*

**Ερώτημα:** κάθε label που στέλνει το front end, υπάρχει στον χάρτη του Worker;

1. Στο `worker/src/index.js` βρες όλα τα table configs — αντικείμενα με κλειδί
   `tblXXXXXXXXXXXXXX` που περιέχουν `fields: {...}`. Για **κάθε** πίνακα φτιάξε
   το πλήρες σύνολο αποδεκτών labels:
   `fields` ∪ `aliases` ∪ `computed` ∪ `links` ∪ `linkAliases` ∪ `reverseLinks`.
2. Στο front end (`core/*.js`, `modules/*.js`) βρες **κάθε** σημείο που χτίζει
   αντικείμενο `fields` για `atCreate`, `atPatch`, `atSafePatch`,
   `atBatchUpdate` — και κάθε `fields[]` σε `atGetAll`.
3. Διασταύρωσε. Παρήγαγε **δύο πίνακες**:

   **Α. ΑΓΝΩΣΤΑ LABELS** — στέλνονται, ο Worker δεν τα ξέρει. Για καθένα:
   `αρχείο:γραμμή`, πίνακας-στόχος, και **κρίσιμα**: στέλνεται *μόνο του*
   (→ `400 No writable fields`, ορατό σφάλμα) ή *μαζί με άλλα*
   (→ **σιωπηλή απώλεια με HTTP 200** — αυτά είναι τα P0);

   **Β. ΑΧΡΗΣΙΜΟΠΟΙΗΤΑ LABELS** — ο Worker τα ξέρει, κανείς δεν τα στέλνει.

**Προσοχή:** τα labels χτίζονται και δυναμικά — `F.STOP_PARENT_ORDER`,
`fields[F.VEROIA_SWITCH]`, template strings, `_dF('...')`. Ανάλυσε το
`core/constants.js` και το `FIELDS`/`F` object του `config.js` για να λύσεις
τις σταθερές. **Μη σταματήσεις στα literals.**

# ΕΡΓΑΣΙΑ 2 — ΠΟΙΑ ΕΡΩΤΗΜΑΤΑ ΘΑ ΠΑΡΟΥΝ 422

Ο μεταφραστής φίλτρων του Worker (`translateTerm`, `applyFilter`,
`preResolveLinkTerms`) δέχεται **περιορισμένη γραμματική**. Διάβασέ την και
κατάγραψε ακριβώς τι υποστηρίζεται.

Μετά βρες **κάθε** `filterByFormula` στο front end (~82 σημεία, πολλά δυναμικά)
και κατάταξέ τα:

| Κατάσταση | Σημασία |
|---|---|
| ✅ Μεταφράζεται | εντάξει |
| ❌ Απορρίπτεται → `422` | **εύρημα** — πες ποιος όρος φταίει |
| ⚠️ Εξαρτάται από runtime τιμή | πες υπό ποια συνθήκη σπάει |

Για κάθε ❌: **υπάρχει `catch` που το κρύβει;** Αν ναι, η σελίδα δείχνει λάθος
δεδομένα αντί να σπάσει — χειρότερο, σημείωσέ το ρητά.

---

# ΕΡΓΑΣΙΑ 3 — ΚΑΘΕ ΣΙΩΠΗΛΗ ΑΠΟΤΥΧΙΑ

Βρες κάθε σημείο όπου μια αποτυχία **δεν φτάνει στον χρήστη**:

- `catch` που κάνει μόνο `console.warn`/`console.log`/τίποτα
- `catch` που πέφτει σε άλλα δεδομένα χωρίς να το πει
- `.catch(() => [])`, `|| []`, `?? {}` που μετατρέπουν σφάλμα σε «άδειο»
- `safeFetch(...)` — τι επιστρέφει στην αποτυχία και τι δείχνει μετά η οθόνη
- toast «επιτυχίας» που τρέχει **πριν** επιβεβαιωθεί η εγγραφή
- ενημέρωση τοπικού state (`r.fields[...] = ...`) **χωρίς** επιβεβαίωση από
  τον server — το μοτίβο του WP-1

Κατάταξη κατά **τι βλέπει ο χρήστης**: (α) λάθος νούμερο σε οθόνη,
(β) **χαμένη εγγραφή με ένδειξη επιτυχίας ← P0**, (γ) κενή λίστα αντί σφάλματος.

# ΕΡΓΑΣΙΑ 4 — ΔΙΚΑΙΩΜΑΤΑ: τρία σημεία που πρέπει να συμφωνούν

1. `config.js` → `PERMS` (τι κρύβει το UI)
2. `core/router.js` → gating ανά σελίδα (`can()`, `item.role`)
3. `worker/src/index.js` → RBAC ανά πίνακα και μέθοδο — **το μόνο πραγματικό όριο**

Φτιάξε πίνακα ρόλος × πίνακας × μέθοδος για τους 5 ρόλους (`owner`,
`management`, `dispatcher`, `accountant`, `warehouse`) και σημείωσε:

- **UI επιτρέπει, Worker απαγορεύει** → ο χρήστης βλέπει κουμπί που δίνει 403
- **Worker επιτρέπει, UI κρύβει** → διαρροή αν κάποιος αλλάξει το `?page=`
- Ρόλος που λείπει εντελώς από τη μία πλευρά

Επίσης: υπάρχουν **τρεις** λίστες χρηστών που πρέπει να συμφωνούν —
`config.js` `USERS`, το ανεξάρτητο αντίγραφο στο `index.html`, και ο πίνακας
`users` της βάσης. Τον τρίτο **δεν τον βλέπεις** — σύγκρινε τους δύο πρώτους
και δήλωσε ρητά ότι ο τρίτος δεν ελέγχθηκε.

# ΕΡΓΑΣΙΑ 5 — ΝΕΚΡΟΣ ΚΩΔΙΚΑΣ ΚΑΙ ΝΕΚΡΑ ΠΕΔΙΑ

- **Πίνακες που δεν υπάρχουν:** το `TABLES` του `config.js` έχει κλειδιά που ο
  Worker δεν χαρτογραφεί (→ `404 Table not available on this backend`). Βρες τα
  όλα, **ποιος κώδικας τα καλεί ακόμη**, και τι δείχνει τότε η οθόνη.
- **Διπλά κλειδιά σε object literals** — ένα είναι γνωστό (`SCAN_TRAINING`
  δηλώνεται δύο φορές στο `TABLES`, κερδίζει το δεύτερο). Ψάξε για άλλα σε
  **όλα** τα αρχεία.
- **Πεδία που διαβάζονται και δεν γράφονται ποτέ** (μοτίβο WP-7).
- **Συναρτήσεις που ορίζονται και δεν καλούνται**, και handlers σε inline
  `onclick=` που δεν υπάρχουν στο `window` — έχει ξανασυμβεί (`_removeStop`,
  `_plateField`).

# ΕΡΓΑΣΙΑ 6 — ΑΣΦΑΛΕΙΑ

# ΓΝΩΣΤΕΣ ΠΑΓΙΔΕΣ — μη βγάλεις ψευδή ευρήματα

- **Το `national_orders` είναι ΣΩΣΤΑ άδειο.** Απόφαση owner: το Veroia Switch
  γράφει **κατευθείαν** στο `NAT_LOADS`, χωρίς ενδιάμεσο national order — δες
  `modules/orders_intl.js:853` και `:1662`. Τιμολογείται μόνο το international
  order. **Το `CLAUDE.md:136` περιγράφει ακόμη το παλιό v1 και είναι ΛΑΘΟΣ** —
  μην το πάρεις ως προδιαγραφή. Το `ARCHITECTURE.md:12` είναι σωστό.
- `'Week Number'` — formula field, **δεν γράφεται**, χωρίς κενό στο όνομα.
- `'Adress'` με ένα `d` στους PARTNERS — δεν είναι typo.
- `'Veroia Switch'` — χωρίς κενό στο τέλος.
- Linked records: `['recABC']` σκέτο string array, **όχι** `[{id:...}]`.
- Checkbox σε φίλτρο: `{Πεδίο}=1`, **όχι** `TRUE()`.
- Το `petras-tms-backend-staging` λέγεται «staging» αλλά **ΕΙΝΑΙ το
  παραγωγικό** — ιστορικό όνομα, δες `worker/wrangler.toml`.
- Τα `_wiCurrentWeek`/`_wnCurrentWeek` χρησιμοποιούν Sunday-start ενώ τα
  υπόλοιπα `isoWeekNumber`. **Γνωστό** — μην το γράψεις ως νέο.
