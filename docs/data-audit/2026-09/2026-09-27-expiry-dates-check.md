**Αφορμή:** ο Θοδωρής είδε λήξεις «ανάποδα» — «5 Ιουνίου φαίνεται 06/05/2026».
**Πηγή που δόθηκε:** Drive «ΗΜΕΡΟΜΗΝΙΕΣ ΛΗΞΗΣ pro .xlsx», φύλλα ΕΛΛΑΔΑ + ΒΟΥΛΓΑΡΙΑ.
**Μέθοδος:** γράφος πηγή → εισαγωγή → Postgres → Worker → οθόνη/φόρμα, κάθε ακμή
ελέγχθηκε χωριστά (subagents), και κάθε αμφίσημη ημερομηνία (ημέρα ≤ 12) κρίθηκε
απέναντι στο **έγγραφο** (ΚΤΕΟ / πράσινη κάρτα / συμβόλαιο στο Drive).

## Ευρήματα ανά ακμή

| Ακμή | Αποτέλεσμα |
|---|---|
| xlsx → Postgres | **Πιστή.** 201/201 κοινά κελιά ίδια, 0 αντιστροφές. Η εισαγωγή διάβαζε την αποθηκευμένη τιμή, όχι το κείμενο. |
| έγγραφο → xlsx | Το φύλλο εμφανίζει με `mm-dd-yy` (αμερικάνικα) και έχει **ανάμεικτη πληκτρολόγηση** ημ/μήνα — ήδη γνωστό από `docs/data-cleanup/COMPLIANCE-AUDIT-2026-08-06.md`. 87 αμφίσημα κελιά → έλεγχος σε έγγραφα: **1 πραγματική αντιστροφή** (IAB2106 ΚΕΚ), 2 λάθος ημέρα/πεδίο, και παλιές τιμές μετά από ανανέωση. |
| Postgres → οθόνες | Όλες οι οθόνες δείχνουν ημέρα-πρώτα (ρητό locale `en-GB`/`el-GR` ή χειροκίνητο split). Καμία δεν μπορεί να δείξει ΜΜ/ΗΗ. |
| φόρμα → Postgres | Το `<input type="date">` γράφει πάντα ISO — **καμία αντιστροφή στην εγγραφή**. Όμως **σχεδιάζεται στη γλώσσα του browser**: σε English (US) δείχνει ΜΜ/ΗΗ. **Αυτό είδε ο Θοδωρής.** |
| σελίδα λήξεων (inline) | Αποθήκευε σε **κάθε** `change` — ο native έλεγχος το πυροδοτεί ανά συμπληρωμένο τμήμα. audit_log P47331 25/9 14:56–57: 5 PATCH (`09-01→09-02→09-26→08-26→2027-08-26`). Μισή πληκτρολόγηση άφηνε λάθος τιμή. |
