## 🚨 P0 — Άμεσης δράσης (αυτή την εβδομάδα)

### 1. petras-assign: δημόσιο PAT + ενεργό split-brain
- **Και τα 8 HTML** του petras-assign κουβαλούν το **τρέχον** Airtable PAT
  hardcoded (π.χ. national_consolidation.html:422, trip_costs.html:417) και
  απαντούν **HTTP 200 χωρίς login** (επιβεβαιωμένο εμπειρικά σήμερα).
  Οποιοσδήποτε στο internet έχει πλήρες read/write/delete στην παραγωγική
  βάση. Το ίδιο PAT υπάρχει και στο git history του TMS repo (το PR #22
  καθάρισε μόνο το HEAD)· το config.js παραδέχεται «scheduled for revocation»
  — **δεν έχει ανακληθεί**.
- Χειρότερα: το National Pick Ups iframe (router.js:269) **γράφει consolidations
  στο παγωμένο Airtable από τις 28/7** — φαίνονται επιτυχείς, δεν φτάνουν ποτέ
  στο TMS/Supabase. Ό,τι consolidation έγινε μετά το cutover είναι σε λάθος βάση.
- **Δράση:** (α) ΑΝΑΚΛΗΣΗ του PAT σήμερα· (β) έλεγχος τι consolidations έγιναν
  μετά τις 28/7 και χειροκίνητη μεταφορά· (γ) μπλοκάρισμα του route/σελίδων
  μέχρι να περάσουν από τον Worker· (δ) ερώτημα στη Valuedriven γιατί το
  PU-T1/PU-T2 (γνωστά από 11/7) δεν μπήκαν στο scope.

### 2. Καμία λήψη backup της live Supabase
Το scripts/backup.sh στοχεύει ακόμα το Airtable ΚΑΙ είναι νεκρό (το token
αφαιρέθηκε). Κανένα pg_dump/export/schedule πουθενά. Σύστημα σε καθημερινή
παραγωγή χωρίς κανένα δίχτυ. **Δράση:** scheduled Supabase export (GH Action
+ secret) με δοκιμασμένο restore — ώρες δουλειάς, όχι μέρες.

### 3. Sentry: καλωδιωμένο, ΣΒΗΣΤΟ
`TMS_SENTRY_DSN = ''` (config.js:36) — και τα δύο paths διορθώθηκαν αλλά
διαβάζουν κενό string· μηδέν production error reporting. **Δράση:** μία
γραμμή (DSN) + bump. Το ίδιο το config.js γράφει: «EMPTY = THE APP HAS NO
PRODUCTION ERROR REPORTING».

## P1 — Σύντομα (2-4 εβδομάδες, κυρίως Valuedriven)

1. **RBAC ανά πίνακα στον server — ΑΝΕΠΑΛΗΘΕΥΤΟ.** Ο μόνος server κώδικας στο
   repo (worker/ = παλιός Worker 1) ελέγχει ΜΟΝΟ αν το JWT είναι έγκυρο — κάθε
   ρόλος μπορεί να διαβάσει κάθε πίνακα. Ο παραγωγικός Worker 2 (Supabase) **δεν
   υπάρχει σε κανένα repo σε αυτό το μηχάνημα** — το «owner-only» δεν μπορεί να
   επαληθευτεί. _Ζήτησε πρόσβαση στο source του petras-tms-backend._
2. **Metrics Audit ≠ owner-only:** gate σε `can('settings')` που έχουν owner ΚΑΙ
   management (router.js:316, config.js:328-331) — αντίθετο με την απόφαση §10.2 #11.
3. **Τα 3 concurrency bugs ζωντανά:** WI-T1 (unmatch/clear αγνοούν conflict,
   weekly_intl.js:1129/1618), WN-T1 (weekly_natl.js:740-741), client-side
   αρίθμηση τιμολογίων (invoicing.js:118-130). Μικρά fixes, γνωστά από 11/7.
4. **CI χωρίς tests:** μόνο το fail-open ratchet τρέχει· το e2e job αποσύρθηκε·
   χωρίς branch protection στο main. Unit tests ελέγχουν δικά τους αντίγραφα
   της λογικής (test-business.js:62). Το e2e γράφει σε production by default
   (playwright.config.js baseURL) — θέλει staging στόχο + cred-gated CI job.
5. **sw.js εκτός εποχής:** το API branch πιάνει μόνο api.airtable.com → τα
   Worker responses cache-άρονται χωρίς όριο/ηλικία, mutations πετάνε
   rejections, το precache δεν σερβίρει ποτέ (unversioned URLs)· financial
   responses μένουν σε Cache Storage σε κοινόχρηστα μηχανήματα.
6. **Prod bundle νεκρό:** app.prod.html δείχνει σε ανύπαρκτα dist/ αρχεία, το
   build.sh ξεχνάει 8 αρχεία — όλοι φορτώνουν 24 unminified scripts (~1,3 MB).
7. **CEO dashboard interval leak** (7 βαριά queries/10λ μετά την έξοδο) +
   **global poller** που τραβά ΟΛΟ το ORDERS ανά 5λ σε κάθε χρήστη.
8. **Veroia Cross-Dock απροστάτευτο:** το recJucKOhC1zh4IP3 διαγράφεται όπως
   κάθε location (locations.js:477-487) — σπάει όλο το VS chain.
