# 02 — Σταθερός έλεγχος χωρίς μοντέλο (Εργασία 2)

Σύνταξη 22/9/2026 · session «Grok Bot ελεγκτής» · **πρόταση, καμία υλοποίηση, τίποτα δεν ενεργοποιήθηκε**. Όλα τα SQL είναι `SELECT` και **έτρεξαν σήμερα μία φορά χειροκίνητα** για την «τιμή 22/9». Στήλες επαληθευμένες σε `information_schema.columns`. Ορισμοί όψεων/triggers διαβάστηκαν **από τη ζωντανή βάση** (`pg_get_viewdef`, `pg_get_functiondef`) και από τα αρχεία migration.

Αρχή: **η απόδειξη είναι ο πίνακας, όχι η οθόνη** (αρχή 2). Κάθε έλεγχος = ένα νούμερο, ένα όριο, μία από τρεις καταστάσεις.

## Οι τρεις καταστάσεις — και γιατί το γκρι δεν είναι πράσινο

| Κατάσταση | Ορισμός | Παράδειγμα 22/9 |
|---|---|---|
| 🟢 **ΠΡΑΣΙΝΟ** | Ο έλεγχος **ολοκληρώθηκε** και πέρασε | `dl_v_rt_gap` = 0 |
| 🔴 **ΚΟΚΚΙΝΟ** | Ολοκληρώθηκε και **παραβίασε** τον κανόνα | — (κανένα σήμερα στα SQL) |
| ⚪ **ΓΚΡΙ** | **Δεν εκτελέστηκε**, η πηγή απέτυχε, τα στοιχεία είναι ανεπαρκή ή **παλιά** | `app_errors` χωρίς εγγραφή 5 ημέρες = ΓΚΡΙ (δεν ξέρουμε αν φτάνουν τα posts)· CF χωρίς token = ΓΚΡΙ |

Κάθε έλεγχος κρατά **χρόνο τελευταίου ΕΠΙΤΥΧΗΜΕΝΟΥ run** (πράσινου ή κόκκινου). **Απουσία αποτελέσματος ≠ υγεία.** Έλεγχος πράσινος χθες χωρίς αποτέλεσμα σήμερα = ΓΚΡΙ + ειδοποίηση μηχανισμού.

| ΝΑΙ — Worker/βάση/CF | ΟΧΙ — μένει στον browser του κάθε εργαζόμενου |

## Επιβάρυνση — τι κοστίζει ένα SELECT σήμερα

Μεγέθη 22/9 (`pg_total_relation_size`, `n_live_tup`): `audit_log` 6.343 γρ./7,4 MB · `dl_entries` 11.170/3,3 MB · `app_errors` 1.522/1,7 MB · `ct_cost_lines` 641/0,9 MB · `order_stops` 761/0,4 MB · `orders` 215/0,2 MB · όλα τα υπόλοιπα < 0,3 MB. **Όλη η βάση χωρά στη μνήμη.** Κάθε έλεγχος παρακάτω σαρώνει το πολύ μερικές χιλιάδες γραμμές· ένας πλήρης κύκλος (40 SELECT) είναι **δευτερόλεπτα, όχι λεπτά**, και μηδενικό κόστος στο free tier. Οι μόνοι που θέλουν χρονικό φίλτρο για να μείνουν φθηνοί καθώς μεγαλώνουν: όσοι διαβάζουν `audit_log`, `dl_entries`, `app_errors` (σημειώνονται με ⚠️). Οι έλεγχοι CF (Α4, Α5, Β4, Β5) κοστίζουν ένα API call ο καθένας και **δεν** επιβαρύνουν τη βάση.

## Ορισμοί που ΔΕΝ πρέπει να θεωρηθούν απόδειξη πληρότητας

Το ότι μια όψη υπάρχει και δίνει 0 **δεν** σημαίνει ότι όλα καλά — σημαίνει ότι ό,τι **μετρά** είναι 0. Τι δεν μετρά η καθεμία (διαβάστηκε ο ορισμός):

| Όψη / κανόνας | Τι μετρά | Τι ΔΕΝ πιάνει |
|---|---|---|
| `dl_v_rt_gap` (011) | RT `OWNED`, με οδηγό, μη ακυρωμένα, **χωρίς καμία** ζωντανή `dl_entries` | RT PARTNER · RT χωρίς οδηγό · `dl_entries` που υπάρχει αλλά με `trip_value IS NULL` (γραμμή «άδεια» — 4.519 τέτοιες ζωντανές σήμερα, κυρίως Excel) |
| `pl_v_order_gate` (007) | Στάσεις φόρτωσης `orders`↔`order_stops` με κίνηση `LOADING`+`confirmed` | Εκφορτώσεις · `national_loads`/`ramp` · κινήσεις `pending` (51 σήμερα) · παραγγελίες **χωρίς καμία στάση φόρτωσης** λείπουν εντελώς από την όψη |
| `ct_v_rt_pallet_gate` (007) | Σκέλη RT με `pallet_exchange=true` καλυμμένα από `PARTNER_PICKUP/DROPOFF` confirmed | Ιδιόκτητα δρομολόγια (μόνο partner events) · pending |

| Τιμολόγηση (043, trigger `invoice_mark_guard`, **ζωντανός στη βάση 22/9**) | Σε INSERT/UPDATE των `invoiced, invoice_number, price` σε `orders` **και** `national_orders`: αν `invoiced=true` και (νέο, ή αλλαγή από false, ή αλλαγή αριθμού/τιμής) → απαιτεί αριθμό ≠ κενό **και** `price > 0` | Τις 2 προϋπάρχουσες γραμμές 21/8 (δεν τις αγγίζει) · `national_loads` (τα VS δεν έχουν invoiced) · update που θέτει `invoiced=false` **και** σβήνει τον αριθμό ταυτόχρονα (παρακάμπτει τον έλεγχο — αποδεκτό, είναι «ξε-τιμολόγηση») |
| Σπάσιμο κύκλου RT (037, trigger `rt_link_split`) | Γράφει `audit_log` με `action='update'`, `after_data->>'split'='true'`, `reason` «split: …» | **Όχι** `action='split'` — ο έλεγχος πρέπει να κοιτά το `after_data`. Σήμερα 0 συνολικά |
