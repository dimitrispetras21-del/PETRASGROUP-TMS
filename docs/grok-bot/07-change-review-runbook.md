# 07 — Runbook: Ελεγκτής προτεινόμενων αλλαγών (ρόλος 1, πιλότος βήματος 5)

Έγκριση owner 22/9/2026 (βήμα 5 του `00-ΠΡΟΤΑΣΗ.md`). Διάρκεια πιλότου: 1 εβδομάδα. Εργαλείο: Claude Code session με τα εγχειρίδια του repo. **Ο ελεγκτής διαβάζει μόνο. Δεν αλλάζει, δεν κάνει push, δεν αγγίζει βάση ή Cloudflare.**

## 1. Πότε

- **Πριν** από κάθε push στο `main` (προτιμώμενο): ο συντονιστής ζητά αξιολόγηση με το SHA του τοπικού commit ή του branch, και δίνει «go» **μετά** το αποτέλεσμα.
- **Μετά** από push που έγινε χωρίς αξιολόγηση: ίδια διαδικασία, το αποτέλεσμα μπορεί μόνο να ζητήσει revert.

## 2. Τι ζητά ο συντονιστής (copy-paste)

```
ΑΞΙΟΛΟΓΗΣΗ ΑΛΛΑΓΗΣ — ρόλος 1
SHA: <7+ χαρακτήρες>   Branch: <όνομα ή "main">   Repo: dimitrispetras21-del/PETRASGROUP-TMS
Εγχειρίδια: docs/grok-bot/skill-tms-knowledge.md (sha256 πρώτα 12: <…>) · CLAUDE.md (sha256 πρώτα 12: <…>)
Οδηγίες: docs/grok-bot/04-πιλότος.md §1Α (Μ1–Μ8) και §1Β (5 ερωτήσεις).
Όρια: μόνο Read/Grep/Glob στο repo στο σημείο του SHA και git show <SHA>. Καμία αλλαγή, κανένα push, καμία βάση/CF, κανένα test, κανένα node.
Απάντησε: ΕΓΚΡΙΝΕΤΑΙ / ΕΓΚΡΙΝΕΤΑΙ ΜΕ ΠΑΡΑΤΗΡΗΣΕΙΣ / ΜΠΛΟΚΑΡΕΤΑΙ + αιτιολογία ≤10 γραμμές (αρχείο:γραμμή) + Μηχανικά Μ1–Μ8 + ΔΕΝ ΕΛΕΓΧΘΗΚΕ.
Γράψε το αποτέλεσμα στο docs/grok-bot/reviews/<YYYY-MM-DD>-<sha7>.md (νέο αρχείο, χωρίς commit).
```

Τα hashes των εγχειριδίων: `shasum -a 256 docs/grok-bot/skill-tms-knowledge.md CLAUDE.md` (στις 22/9: `7e4697980ebb` / `72a4c258b5db`). **Αν αλλάξει το hash, οι παλιές αξιολογήσεις δεν συγκρίνονται με τις νέες.**

## 3. Πώς τρέχει ο ελεγκτής (μέσα στο session)

1. `git fetch` και `git show <SHA> --stat`, μετά `git show <SHA>` (το diff). Αν ο SHA είναι σε branch που δεν υπάρχει τοπικά: `git fetch origin <branch>`.
2. Για τον κώδικα «όπως είναι στο SHA» χωρίς να αγγίξει το working tree: `git worktree add --detach <scratchpad>/review-<sha7> <SHA>` — και **αφαίρεση** μετά (`git worktree remove`).
3. Διαβάζει τα 2 εγχειρίδια, τρέχει Μ1–Μ8 **με grep/ανάγνωση** (χωρίς `node`, χωρίς tests — στο benchmark της 22/9 ένας ελεγκτής έτρεξε `node -c` παρά την απαγόρευση· αναφέρεται ως παρέκκλιση), απαντά στις 5 ερωτήσεις του §1Β.
4. Γράφει το αρχείο αναφοράς (§4). **Δεν** το κάνει commit — ο συντονιστής αποφασίζει αν οι αναφορές μπαίνουν στο repo (πρόταση: ναι, μία φορά την εβδομάδα, μαζί).
5. Επιστρέφει στον συντονιστή τις ≤10 γραμμές + τη διαδρομή του αρχείου.

Χρόνος-στόχος: ≤ 15 λεπτά ανά αλλαγή. Αν το diff > 100 KB, ο ελεγκτής το λέει και αξιολογεί **μόνο** τα αρχεία front-end εγγραφών, χάρτη πεδίων, δικαιωμάτων, `sw.js`/`app.html` — και γράφει τι παρέλειψε.

## 4. Μορφή αρχείου `docs/grok-bot/reviews/<YYYY-MM-DD>-<sha7>.md` (≤ 1 οθόνη)

```
# Αξιολόγηση <sha7> — <YYYY-MM-DD HH:MM>
Commit: <sha> · <τίτλος commit, κομμένος στα 100 χαρακτήρες>
Εγχειρίδια: knowledge <hash12> · CLAUDE <hash12> · Ελεγκτής: <μοντέλο/εργαλείο>
Diff: <N> αρχεία, <K> KB · Χρόνος: <λεπτά> · Tokens: <από τον μετρητή, ή "εκτίμηση bytes/3">

ΑΠΟΤΕΛΕΣΜΑ: ΕΓΚΡΙΝΕΤΑΙ | ΕΓΚΡΙΝΕΤΑΙ ΜΕ ΠΑΡΑΤΗΡΗΣΕΙΣ | ΜΠΛΟΚΑΡΕΤΑΙ

ΜΗΧΑΝΙΚΑ: Μ1 pass · Μ2 pass · Μ3 fail · Μ4 pass · Μ5 n.a. · Μ6 pass · Μ7 n.a. · Μ8 n.a.

ΕΥΡΗΜΑΤΑ (0–5, καθένα με τα 7 πεδία):
1. ΤΙ: <μία πρόταση>
   ΠΟΥ: <αρχείο:γραμμή>
   ΚΑΝΟΝΑΣ: <Μx ή ερώτηση 1Β-y ή κλειδωμένη απόφαση + πηγή>
   ΕΠΙΠΤΩΣΗ: <ποιος χρήστης, ποια οθόνη, τι θα δει λάθος>
   ΣΟΒΑΡΟΤΗΤΑ: P1 / P2 / P3 / P4
   ΒΕΒΑΙΟΤΗΤΑ: ΕΠΙΒΕΒΑΙΩΜΕΝΟ (διάβασα τον κώδικα) / ΠΙΘΑΝΟ / ΥΠΟΘΕΣΗ
   ΕΠΟΜΕΝΟ: <τι κάνει ο συγγραφέας της αλλαγής — όχι ο ελεγκτής>

ΔΕΝ ΕΛΕΓΧΘΗΚΕ: <λίστα ή "τίποτα">
ΠΡΟΤΑΣΗ ΕΓΧΕΙΡΙΔΙΟΥ (προαιρετικό): <κενό που βρέθηκε — δεν διορθώνεται εδώ>
```

Κανόνες: ΜΠΛΟΚΑΡΕΤΑΙ μόνο με ≥1 εύρημα P1/P2 **ΕΠΙΒΕΒΑΙΩΜΕΝΟ**. ΥΠΟΘΕΣΗ ποτέ δεν μπλοκάρει. Κανένα όνομα εργαζομένου/πελάτη στην αναφορά (το repo είναι δημόσιο).

## 5. Τι ΔΕΝ κάνει ο ελεγκτής

- Καμία επεξεργασία αρχείων του repo εκτός από το **νέο** αρχείο `reviews/…`.
- Κανένα `git push`, `commit`, `checkout` στο working tree του συντονιστή, `stash`.
- Καμία πρόσβαση σε Supabase, Cloudflare, `.env.local`, MCP με κλειδιά.
- Δεν τρέχει tests/rigs/`node` (τα αναφέρει ως «πρέπει να τρέξουν»).
- Δεν «διορθώνει» — δεν προτείνει patch, μόνο λέει τι σπάει και ποιος κανόνας.
- Δεν αλλάζει τα εγχειρίδια. Αν βρει κενό, το γράφει ως «ΠΡΟΤΑΣΗ ΕΓΧΕΙΡΙΔΙΟΥ» στο τέλος της αναφοράς.

## 7. Πρώτη πραγματική αξιολόγηση

Η πρώτη αξιολόγηση θα γίνει στο επόμενο push του session τιμολόγησης (alias `#invoicing` → όψη Παραγγελιών), **πριν** το push, με SHA + branch από τον συντονιστή. Ο φάκελος `docs/grok-bot/reviews/` δημιουργείται τότε.
