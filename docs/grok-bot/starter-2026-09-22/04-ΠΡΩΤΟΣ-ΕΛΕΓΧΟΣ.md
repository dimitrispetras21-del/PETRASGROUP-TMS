## Μέρος 1 — Απογραφή συνδέσεων

Κατέγραψε **ποιες συνδέσεις όντως έχεις αυτή τη στιγμή** (GitHub / Supabase / Cloudflare / browser / άλλο) και για καθεμία:
- πώς φαίνεται να λειτουργεί (π.χ. «API μέσω token», «connection string», «δεν ξέρω»),
- τι **φαίνεται** να μπορεί: μόνο ανάγνωση ή και εγγραφή — με βάση ό,τι βλέπεις, όχι υπόθεση,
- ποιο repo / project / account δείχνει (όνομα, όχι κλειδί).

Μην τυπώσεις καμία τιμή κλειδιού, token, connection string, κωδικού. Αν μια σύνδεση σου δίνει δυνατότητα εγγραφής, το λες ρητά — και **δεν** τη χρησιμοποιείς για τίποτα.

**Επιχειρησιακοί κανόνες προς έλεγχο (από το `02`, §7):**
1. Το TMS δεν εκδίδει τιμολόγια· σήμανση μόνο με αριθμό ΤΠΥ και τιμή (owner 21/9)· μία πόρτα = Τιμολόγηση (owner 22/9).

4. Δικαιώματα: ποιοι ρόλοι μπορούν σήμερα να γράψουν `Invoiced` σε `orders`/`national_orders` μέσω Worker, από ποιες οθόνες — υπάρχει ακόμη κάποια άλλη πόρτα εκτός Τιμολόγησης;

**Συγκεκριμένα σενάρια αποτυχίας που πρέπει να εξετάσεις** (γράψε για καθένα: συμβαίνει; ΓΕΓΟΝΟΣ/ΥΠΟΘΕΣΗ· ποιος/πού/τι βλέπει):
