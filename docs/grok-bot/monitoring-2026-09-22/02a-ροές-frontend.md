# 02a · Χάρτης ροών χρήστη (front end) — τι γράφει κάθε κλικ, πώς αποτυγχάνει, τι το αποδεικνύει

Βήμα 2a του πακέτου αυτόματης παρακολούθησης. Ημερομηνία ανάγνωσης κώδικα: **22/9/2026**, `main` (55f101c).
Μόνο ανάγνωση repo· καμία μέτρηση στη βάση εδώ (οι μετρήσεις ζουν στο `02-έλεγχοι.md`).

**Πηγές:** `core/router.js:23-94` (NAV), `config.js:333-346` (PERMS), `core/api.js`, `core/order-sync.js`,
`core/rt-feed.js`, `core/pallet-feed.js`, `sw.js`, `modules/*.js`, `docs/SYNC_MAP.md` (E1–E14),
`docs/DECISION_LOG.md`, `docs/grok-bot/skill-tms-knowledge.md` §2, `worker/src/index.js` (μόνο για audit/RBAC).

**Πώς διαβάζεται κάθε ροή:** ποιος ρόλος, ποιο κλικ → ποιο endpoint / πίνακας / στήλες → τι ακολουθεί αυτόματα →
πώς φαίνεται «επιτυχία» (ο πίνακας είναι η απόδειξη, όχι το toast — αρχή 2) → **ΦΑΝΕΡΗ** αποτυχία (toast/4xx) →
**ΣΙΩΠΗΛΗ** αποτυχία (200 OK χωρίς εγγραφή, NULL κρυμμένο, cache, μισή αλυσίδα, offline) → κανόνας που το
τεκμηριώνει → υπάρχουσα κάλυψη → **ελάχιστο σήμα** που θα αποδείκνυε αυτόματα ότι ολοκληρώθηκε.
Όπου ο κώδικας κάνει κάτι που καμία απόφαση δεν τεκμηριώνει: «**ασάφεια — θέλει απόφαση owner**».

Συντομογραφίες: **AL** = γραμμή `audit_log` (actor = username, role, action, table, record_id, before/after) —
ο Worker τη γράφει σε **κάθε** POST/PATCH/DELETE του facade (`worker/src/index.js:2430,2579,2802,2851,2881`),
στα `/costs/*` (3045–3602, 4022–4079), στα `/pallets/*` (4401–4517) και στα `/api/locations` (720). Οι triggers της
βάσης γράφουν με `actor='trigger:<όνομα>'` (order_legs, order_dates_follow, national_load_follow/unlink, order_unlink,
rt_create, rt_create_natl, rt_sync). **FUF** = γραμμή `facade_unknown_fields` (kind=`write`) — από 9/9 ο Worker
καταγράφει το άγνωστο label που έριξε (`logUnknownFields`, γρ. 641), αλλά **ο χρήστης εξακολουθεί να βλέπει 200 OK**.

## 1. Οι ροές

Στήλες: **Ρόλος · κλικ** → **Γράφει** (endpoint / πίνακας.στήλες) → **Παράπλευρα** → **Επιτυχία στην οθόνη** → **ΦΑΝΕΡΗ** αποτυχία → **ΣΙΩΠΗΛΗ** αποτυχία → **Κανόνας** → **Κάλυψη** → **Ελάχιστο σήμα**.

### Α. Συνεδρία

**F-01 · Είσοδος.** Όλοι · `index.html` «Σύνδεση» → POST `/auth/login` (bcrypt `verify_login`) → JWT 8h + `tms_user`. Παράπλευρα: `atPreload`, `preloadReferenceData`, `scanHydrateTrainingCache` (auth.js:46-50). Επιτυχία: μετάβαση `app.html`. ΦΑΝΕΡΗ: 401 «Λάθος όνομα/κωδικός», άλλο status «Ο διακομιστής δεν απάντησε». ΣΙΩΠΗΛΗ: χρήστης που λείπει από `USERS` του `index.html` περνά το login και **πετιέται από τον tamper guard** (auth.js:24-36) χωρίς μήνυμα (CLAUDE.md §Auth). Κανόνας: CLAUDE.md §Auth· SYNC_MAP E14. Κάλυψη: E14 (χειροκίνητα)· 02 Β5. **Σήμα:** δεν επιβεβαιώθηκε αν το `/auth/login` γράφει AL — αν όχι, μόνο CF `POST /auth/login 200` ανά χρήστη· προτείνεται AL `action='login'`.

**F-02 · Λήξη JWT / 401.** Βλ. §0. Facade → επιστροφή στο login· `/costs`, `/pallets`, `/print/pdf` → «HTTP 401» στην οθόνη. **Σήμα:** CF `status=401` ανά διαδρομή (όχι μόνο σύνολο)· `app_errors` με «HTTP 401».

**F-03 · Offline.** Βλ. §0. **Σήμα:** αδύνατο κεντρικά — η ουρά ζει στο localStorage. Έμμεσο: AL με `created_at` πολύ μετά το `Last Modified` που είχε δει ο χρήστης· toast «N αλλαγές συγχρονίστηκαν» δεν καταγράφεται πουθενά. Κενό.

**F-04 · Undo / Κάδος.** Βλ. §0. **Σήμα:** AL `action='create'` σε πίνακα X ≤ 60" μετά από AL `action='delete'` ίδιου πίνακα, ίδιος actor, με `after_data` ≈ `before_data` του delete → «επαναφορά με νέο id» (P2).
