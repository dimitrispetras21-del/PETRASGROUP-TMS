# 05 — Σχέδιο πρώτης εγκατάστασης · τρία κύματα

**ΟΛΟ ΤΟ ΠΕΡΙΕΧΟΜΕΝΟ ΕΙΝΑΙ ΠΡΟΣΧΕΔΙΟ.** Κανένα SQL δεν εκτελέστηκε, κανένα deploy δεν έγινε, καμία ρύθμιση δεν
άλλαξε. Ο κανόνας του έργου ισχύει ακέραιος: **Supabase = SELECT μόνο· κάθε εγγραφή ή migration θέλει ρητή
έγκριση του ιδιοκτήτη στη συνομιλία, πριν εκτελεστεί** (`CLAUDE.md §ΚΑΝΟΝΕΣ ΒΑΣΗΣ`). Κάθε εκτέλεση σε βάση ή
Worker γίνεται **μετά τις 15:00** (ομάδα 05:30–14:30, αρχή 7).

# ΚΥΜΑ 1 — αυτή την εβδομάδα · μηδέν αλλαγή στην εφαρμογή

**Τι πετυχαίνει:** πέντε έλεγχοι που τρέχουν μόνοι τους, πέντε ουρές στην πρωινή σύνοψη, μήνυμα στο τηλέφωνο,
και ένας μηχανισμός που φωνάζει αν πεθάνει ο ίδιος ο ελεγκτής. **Δεν αγγίζει**: κώδικα εφαρμογής, Worker,
υπάρχοντες πίνακες, δεδομένα παραγωγής. Όλα τα SELECT των ελέγχων είναι αυτούσια από το `02b` (μετρημένα 22/9).

### Προαπαιτούμενα (ο ιδιοκτήτης τα κάνει πριν το SQL)
1. **Telegram**: bot από @BotFather → `/start` από το τηλέφωνο → `chat_id` μέσω `getUpdates` (~5′, `03 §Στ5.1`).
2. **ntfy**: εφαρμογή + συνδρομή σε topic 32 τυχαίων χαρακτήρων (το topic **είναι** ο κωδικός).
3. **healthchecks.io**: δωρεάν λογαριασμός, ένα check, κρατάμε το UUID του ping (grace 45′).
4. **Supabase Vault**: επιβεβαίωση ότι υπάρχει στο πλάνο μας — **ΔΕΝ ΕΠΑΛΗΘΕΥΤΗΚΕ** (`03 §Τι ΔΕΝ
   επαληθεύτηκε`). Αν λείπει, τα μυστικά **δεν** μπαίνουν στο `cron.job.command` (είναι αναγνώσιμο) — τότε η
   αποστολή περνά από τον Worker με secret της Cloudflare και το Κύμα 1 **αναβάλλεται μέχρι εκείνο το deploy**.
5. Επιβεβαίωση ότι `pg_cron` / `pg_net` επιτρέπονται στο πλάνο μας — **δευτερογενής πηγή μόνο** (`03 §Στ5.5`).

### Βήμα 1.1 — `047_monitoring_schema.sql` (ΠΡΟΣΧΕΔΙΟ)

```sql
-- 047_monitoring_schema.sql — ΠΡΟΣΧΕΔΙΟ · ο ιδιοκτήτης εκτελεί μετά τις 15:00 · αναστρέψιμο (DROP SCHEMA ... CASCADE)
-- ΓΙΑΤΙ: σήμερα δεν υπάρχει πουθενά η πρόταση «ο τελευταίος πλήρης έλεγχος πέτυχε στις …» (01 §5).
-- Η απουσία αποτελέσματος ΔΕΝ είναι πράσινο: το run_id κρατά πόσοι έλεγχοι έτρεξαν vs πόσοι ήταν ενεργοί.
CREATE EXTENSION IF NOT EXISTS pg_cron;
CREATE EXTENSION IF NOT EXISTS pg_net;
CREATE SCHEMA IF NOT EXISTS monitoring;

CREATE TABLE monitoring.checks (
  id             text PRIMARY KEY,                       -- 'B-01'
  title          text NOT NULL,                          -- ελληνικά, μία γραμμή
  sql_text       text NOT NULL,                          -- ΕΝΑ statement, επιστρέφει ΕΝΑΝ αριθμό
  red_op         text NOT NULL CHECK (red_op IN ('>','>=','<','<=','=','<>')),
  red_value      numeric NOT NULL,
  severity       text NOT NULL CHECK (severity IN ('P1','P2','P3','P4')),
  schedule_tags  text[] NOT NULL,                        -- {'fast'},{'half'},{'hourly'},{'daily'},{'weekly'}
  is_queue       boolean NOT NULL DEFAULT false,         -- ουρά εργασίας: ΠΟΤΕ κόκκινο, μόνο νούμερο στη σύνοψη
  baseline       numeric,                                -- ΙΣΤΟΡΙΚΟ που δεν μετρά ως εύρημα (π.χ. Β-11 = 2)
  note           text,
  enabled        boolean NOT NULL DEFAULT true
);

CREATE TABLE monitoring.results (
  id        bigserial PRIMARY KEY,
  run_id    uuid NOT NULL,
  check_id  text NOT NULL REFERENCES monitoring.checks(id),
  run_at    timestamptz NOT NULL DEFAULT now(),
  value     numeric,                                     -- NULL = δεν επέστρεψε
  status    text NOT NULL CHECK (status IN ('green','red','queue','error')),
  ms        integer,
  err       text
);
CREATE INDEX results_check_time_idx ON monitoring.results (check_id, run_at DESC);

-- Ο πίνακας περιστατικών: σχήμα από το 03 §Στ5.3, με το 'MECH' ως ξεχωριστή σοβαρότητα.
CREATE TABLE monitoring.incidents (
  id bigserial PRIMARY KEY, incident_key text NOT NULL, check_id text NOT NULL,
  entity_table text, entity_id text,
  severity text NOT NULL CHECK (severity IN ('P1','P2','P3','P4','MECH')),
  state text NOT NULL DEFAULT 'new' CHECK (state IN ('new','confirmed','false_alarm','resolved','recurred')),
  value numeric, expected text,
  first_seen timestamptz NOT NULL DEFAULT now(), last_seen timestamptz NOT NULL DEFAULT now(),
  occurrences int NOT NULL DEFAULT 1, package jsonb,
  diagnosis text, diagnosed_at timestamptz, model text, tokens_in int, tokens_out int,
  notified_at timestamptz, notify_channel text, human_note text,
  state_changed_by text, state_changed_at timestamptz, resolved_verified_at timestamptz
);
CREATE UNIQUE INDEX incidents_open_key ON monitoring.incidents (incident_key)
  WHERE state IN ('new','confirmed','recurred');

CREATE TABLE monitoring.limits (name text PRIMARY KEY, value numeric NOT NULL);
INSERT INTO monitoring.limits VALUES
  ('investigations_per_day',5), ('notifications_per_day',20), ('tokens_per_month',2000000);
```

**Η συνάρτηση εκτέλεσης** — γράφει αποτέλεσμα **πάντα**, ακόμη και σε σφάλμα (αρχή 1):

```sql
CREATE OR REPLACE FUNCTION monitoring.run_checks(p_tag text)
RETURNS uuid LANGUAGE plpgsql AS $fn$
DECLARE r monitoring.checks%ROWTYPE; v numeric; t0 timestamptz; g_run uuid := gen_random_uuid();
        st text; expected_n int := 0; ran_n int := 0; key text;
BEGIN
  SELECT count(*) INTO expected_n FROM monitoring.checks WHERE enabled AND p_tag = ANY(schedule_tags);
  FOR r IN SELECT * FROM monitoring.checks WHERE enabled AND p_tag = ANY(schedule_tags) ORDER BY id LOOP
    t0 := clock_timestamp(); v := NULL; st := 'error';
    BEGIN
      EXECUTE r.sql_text INTO v;                                  -- ΕΝΑ statement, ΕΝΑΣ αριθμός
      IF r.is_queue THEN st := 'queue';
      ELSIF v IS NULL THEN st := 'error';                          -- απουσία ΔΕΝ είναι πράσινο
      ELSE
        EXECUTE format('SELECT $1 %s $2', r.red_op) INTO st USING v, coalesce(r.baseline, r.red_value);
        st := CASE WHEN st::boolean THEN 'red' ELSE 'green' END;
      END IF;
    EXCEPTION WHEN OTHERS THEN
      st := 'error';
      INSERT INTO monitoring.results (run_id,check_id,value,status,ms,err)
      VALUES (g_run, r.id, NULL, 'error',
              (extract(epoch FROM clock_timestamp()-t0)*1000)::int, left(SQLSTATE||' '||SQLERRM,200));
      CONTINUE;
    END;
    ran_n := ran_n + 1;
    INSERT INTO monitoring.results (run_id,check_id,value,status,ms)
    VALUES (g_run, r.id, v, st, (extract(epoch FROM clock_timestamp()-t0)*1000)::int);

    key := r.id || '::';                                           -- 03 §Στ5.3: check_id:table:id (εδώ σε επίπεδο ελέγχου)
    IF st = 'red' THEN
      INSERT INTO monitoring.incidents (incident_key,check_id,severity,value,expected,state)
      VALUES (key, r.id, r.severity, v, r.red_op||' '||r.red_value, 'new')
      ON CONFLICT (incident_key) WHERE state IN ('new','confirmed','recurred')
      DO UPDATE SET last_seen = now(), occurrences = monitoring.incidents.occurrences + 1,
                    value = EXCLUDED.value;
    ELSIF st = 'green' THEN
      UPDATE monitoring.incidents SET state='resolved', resolved_verified_at=now(),
             state_changed_by='run_checks', state_changed_at=now()
       WHERE incident_key = key AND state IN ('new','confirmed','recurred');
    END IF;
  END LOOP;

  -- ΜΗΧΑΝΙΣΜΟΣ: έτρεξαν λιγότεροι από τους ενεργούς ⇒ κόκκινο ΜΗΧΑΝΙΣΜΟΥ, ποτέ σιωπή (03 §Στ4)
  IF ran_n < expected_n THEN
    INSERT INTO monitoring.incidents (incident_key,check_id,severity,value,expected,state)
    VALUES ('MECH:run:'||p_tag, 'MECH', 'MECH', ran_n, 'ran = '||expected_n, 'new')
    ON CONFLICT (incident_key) WHERE state IN ('new','confirmed','recurred')
    DO UPDATE SET last_seen=now(), occurrences=monitoring.incidents.occurrences+1, value=EXCLUDED.value;
  END IF;

  -- Dead-man ΕΞΩ από τη Supabase: δεν υπάρχει SQL που να πιάνει τον θάνατο του SQL (03 §Στ4)
  PERFORM net.http_get(url := 'https://hc-ping.com/' ||
          (SELECT decrypted_secret FROM vault.decrypted_secrets WHERE name='hc_uuid'),
          timeout_milliseconds := 8000);
  RETURN g_run;
END $fn$;
```

**⚠️ Ρίσκο που πρέπει να εγκριθεί συνειδητά:** το `sql_text` ζει σε πίνακα και εκτελείται δυναμικά. Όποιος
μπορεί να κάνει `UPDATE monitoring.checks` **εκτελεί ό,τι θέλει με τα δικαιώματα του ιδιοκτήτη της συνάρτησης**.
Γι' αυτό: η συνάρτηση **δεν** είναι `SECURITY DEFINER`, και ο ρόλος `tms_monitor` (Κύμα 2) παίρνει **μόνο
SELECT** στον `monitoring.checks` — ποτέ UPDATE. Εναλλακτική αν αυτό δεν είναι αποδεκτό: δέκα ξεχωριστές
συναρτήσεις με σταθερό SQL μέσα τους (περισσότερος κώδικας, μηδενική δυναμική εκτέλεση).

### Βήμα 1.3 — `048_monitoring_notify.sql` (ΠΡΟΣΧΕΔΙΟ)

```sql
-- 048_monitoring_notify.sql — ΠΡΟΣΧΕΔΙΟ · μετά τις 15:00 · αναστρέψιμο
-- Τα μυστικά ΜΟΝΟ στο Vault: το cron.job.command είναι αναγνώσιμο από όποιον διαβάζει τον πίνακα (03 §Στ5.1).
CREATE OR REPLACE FUNCTION monitoring.notify() RETURNS int LANGUAGE plpgsql AS $fn$
DECLARE i record; n int := 0; body text; req bigint;
BEGIN
  FOR i IN SELECT * FROM monitoring.incidents
            WHERE state IN ('new','recurred') AND severity IN ('P1','MECH')
              AND (notified_at IS NULL OR (last_seen > notified_at + interval '24 hours'))
            ORDER BY first_seen LIMIT (SELECT value FROM monitoring.limits WHERE name='notifications_per_day')
  LOOP
    body := CASE WHEN i.severity='MECH' THEN '⚫ ΜΗΧΑΝΙΣΜΟΣ: ' ELSE '🔴 P1 ' END
            || i.check_id || ' = ' || coalesce(i.value::text,'—')
            || ' (αναμ. ' || coalesce(i.expected,'?') || ') από '
            || to_char(i.first_seen AT TIME ZONE 'Europe/Athens','DD/MM HH24:MI')
            || ' · διάγνωση: ' || coalesce(left(i.diagnosis,120),'εκκρεμεί');
    SELECT net.http_post(
      url := 'https://api.telegram.org/bot' || (SELECT decrypted_secret FROM vault.decrypted_secrets WHERE name='tg_token') || '/sendMessage',
      body := jsonb_build_object('chat_id',(SELECT decrypted_secret FROM vault.decrypted_secrets WHERE name='tg_chat'),'text',body),
      timeout_milliseconds := 8000) INTO req;                       -- default 2000 ms είναι λίγο για Telegram
    UPDATE monitoring.incidents SET notified_at = now(), notify_channel = 'telegram:'||req WHERE id = i.id;
    n := n + 1;
  END LOOP;
  RETURN n;
END $fn$;

-- Δεύτερη διαδρομή: αν το Telegram δεν απάντησε 200, φεύγει ntfy. Αν πέσει και αυτό, ΔΕΝ γίνεται το ping
-- του healthchecks.io στο επόμενο run ⇒ ειδοποιεί εκείνο (τρίτη διαδρομή, email) — 03 §Στ4.
CREATE OR REPLACE FUNCTION monitoring.notify_verify() RETURNS int LANGUAGE plpgsql AS $fn$
DECLARE i record; n int := 0; ok boolean;
BEGIN
  FOR i IN SELECT * FROM monitoring.incidents
            WHERE notified_at > now()-interval '30 minutes' AND notify_channel LIKE 'telegram:%' LOOP
    SELECT (status_code = 200) INTO ok FROM net._http_response
     WHERE id = split_part(i.notify_channel,':',2)::bigint;        -- κρατιέται ~6 ώρες (pg_net)
    IF ok IS NOT TRUE THEN
      PERFORM net.http_post(
        url := 'https://ntfy.sh/' || (SELECT decrypted_secret FROM vault.decrypted_secrets WHERE name='ntfy_topic'),
        body := jsonb_build_object('t', i.check_id || ' ' || coalesce(i.value::text,'—')),
        timeout_milliseconds := 8000);
      UPDATE monitoring.incidents SET notify_channel = i.notify_channel || '+ntfy' WHERE id = i.id;
      n := n + 1;
    END IF;
  END LOOP;
  RETURN n;
END $fn$;
```

**Η σύνοψη των 07:00** — φεύγει **και όταν όλα είναι πράσινα** (η σιωπή δεν επιτρέπεται να σημαίνει «εντάξει»,
`03 §Στ5.2`), με πρώτη γραμμή τον τελευταίο επιτυχημένο πλήρη έλεγχο:

```sql
CREATE OR REPLACE FUNCTION monitoring.digest() RETURNS text LANGUAGE sql AS $fn$
  SELECT 'Έλεγχος TMS ' || to_char(now() AT TIME ZONE 'Europe/Athens','DD/MM HH24:MI') || E'\n'
   || 'Τελευταίος πλήρης έλεγχος: '
   || coalesce((SELECT to_char(max(run_at) AT TIME ZONE 'Europe/Athens','DD/MM HH24:MI')
                FROM monitoring.results WHERE status <> 'error'),'ΚΑΝΕΝΑΣ') || E'\n'
   || coalesce((SELECT string_agg('🔴 '||c.id||' '||c.title||': '||r.value, E'\n')
        FROM monitoring.results r JOIN monitoring.checks c ON c.id=r.check_id
        WHERE r.status='red' AND r.run_at>now()-interval '24 hours'), '✅ κανένα κόκκινο') || E'\n'
   || coalesce((SELECT string_agg('• '||c.title||': '||r.value, E'\n')
        FROM monitoring.results r JOIN monitoring.checks c ON c.id=r.check_id
        WHERE r.status='queue' AND r.run_at>now()-interval '24 hours'), '') || E'\n'
   || coalesce((SELECT '⚫ ΔΕΝ ΕΤΡΕΞΑΝ: '||string_agg(check_id,', ')
        FROM monitoring.results WHERE status='error' AND run_at>now()-interval '24 hours'), '');
$fn$;

-- Η αποστολή της σύνοψης: ίδιο κανάλι, χωρίς περιστατικό από πίσω.
CREATE OR REPLACE FUNCTION monitoring.send_digest() RETURNS void LANGUAGE plpgsql AS $fn$
BEGIN
  PERFORM net.http_post(
    url := 'https://api.telegram.org/bot' || (SELECT decrypted_secret FROM vault.decrypted_secrets WHERE name='tg_token') || '/sendMessage',
    body := jsonb_build_object('chat_id',(SELECT decrypted_secret FROM vault.decrypted_secrets WHERE name='tg_chat'),
                               'text', left(monitoring.digest(), 3800)),
    timeout_milliseconds := 8000);
END $fn$;
```

### Βήμα 1.4 — χρονοδιάγραμμα (ΠΡΟΣΧΕΔΙΟ· ώρες **UTC**, Αθήνα = UTC+3 ως 25/10)

```sql
SELECT cron.schedule('tms-fast',   '*/15 2-11 * * 1-6', $$SELECT monitoring.run_checks('fast')$$);    -- 05:00–14:45 Αθήνα
SELECT cron.schedule('tms-half',   '*/30 3-11 * * 1-6', $$SELECT monitoring.run_checks('half')$$);    -- 06:30–14:30
SELECT cron.schedule('tms-hourly', '5 * * * *',         $$SELECT monitoring.run_checks('hourly')$$);
SELECT cron.schedule('tms-daily',  '0 2 * * *',         $$SELECT monitoring.run_checks('daily')$$);   -- 05:00 Αθήνα
SELECT cron.schedule('tms-notify', '*/5 * * * *',       $$SELECT monitoring.notify()$$);
SELECT cron.schedule('tms-verify', '*/10 * * * *',      $$SELECT monitoring.notify_verify()$$);
SELECT cron.schedule('tms-digest', '0 4 * * *',         $$SELECT monitoring.send_digest()$$); -- 07:00 Αθήνα
```

**Απόκλιση από το `03 §0` — δηλωμένη:** το `03` έδειχνε όλα στις 03:00–03:15. Εδώ οι έλεγχοι τρέχουν **μέσα
στη βάρδια**, γιατί το `02b` ορίζει τα Β-01/Β-26 «κάθε 15′ 05:00–15:00» και το Β-35 μετρά σιωπή **μέσα** στη
βάρδια — στις 03:00 και τα δύο θα ήταν άσκοπα. Η **σύνοψη** μένει πριν τη βάρδια (07:00). ⚠️ **Αλλαγή ώρας
25/10**: οι εκφράσεις είναι UTC και δεν αλλάζουν μόνες τους — μπαίνει υπενθύμιση στον ιδιοκτήτη.

### Επαλήθευση Κύματος 1 (SELECT, ο ιδιοκτήτης ή ο συντονιστής τα τρέχει)
```sql
SELECT jobname, schedule, active FROM cron.job WHERE jobname LIKE 'tms-%';                    -- 7 γραμμές, active
SELECT check_id, status, value, run_at FROM monitoring.results ORDER BY run_at DESC LIMIT 20; -- γεμίζει
SELECT count(*) FILTER (WHERE status='error') AS den_etrexan, count(*) AS synolo
  FROM monitoring.results WHERE run_at > now()-interval '2 hours';                            -- den_etrexan = 0
SELECT id, check_id, severity, state, notified_at FROM monitoring.incidents ORDER BY id DESC LIMIT 10;
```
**Τι γίνεται «επαληθευμένο» μετά:** ότι οι δέκα έλεγχοι τρέχουν μόνοι τους και αφήνουν ίχνος. **Δεν** γίνεται
επαληθευμένο ότι η ειδοποίηση φτάνει — αυτό το αποδεικνύει **μόνο** το `07-σχέδιο-επαλήθευσης-αλυσίδας.md`.

**Αναστροφή Κύματος 1:** `SELECT cron.unschedule(jobname) FROM cron.job WHERE jobname LIKE 'tms-%';` και
`DROP SCHEMA monitoring CASCADE;`. Χρόνος: λεπτά. Καμία επίπτωση σε δεδομένα παραγωγής.

### 2.3 Ρόλος `tms_monitor`
```sql
-- 050_tms_monitor_role.sql — ΠΡΟΣΧΕΔΙΟ · GRANT πριν από κάθε REVOKE (αρχή 7) · αναστρέψιμο (DROP ROLE)
CREATE ROLE tms_monitor LOGIN PASSWORD '<από τον ιδιοκτήτη, ποτέ σε αρχείο>';
GRANT USAGE ON SCHEMA public, monitoring TO tms_monitor;
GRANT SELECT ON monitoring.checks, monitoring.results, monitoring.incidents, monitoring.limits TO tms_monitor;
GRANT INSERT, UPDATE (diagnosis, diagnosed_at, model, tokens_in, tokens_out) ON monitoring.incidents TO tms_monitor;
-- ΡΗΤΗ λίστα SELECT στο public (ΠΟΤΕ users· ΠΟΤΕ audit_log.before_data/after_data — μέσω όψης):
GRANT SELECT ON public.orders, public.order_stops, public.national_loads, public.national_orders,
  public.groupage_lines, public.consolidated_loads, public.ramp, public.ct_round_trips, public.ct_rt_legs,
  public.ct_cost_lines, public.ct_cost_docs, public.dl_entries, public.pl_movements, public.app_errors,
  public.facade_unknown_fields, public.locations, public.trucks, public.trailers TO tms_monitor;
CREATE VIEW monitoring.v_audit AS SELECT id, created_at, actor, role, action, table_name, record_id FROM public.audit_log;
GRANT SELECT ON monitoring.v_audit TO tms_monitor;   -- χωρίς before_data/after_data
```
**Γιατί έχει σημασία:** σήμερα ο ελεγκτής συνδέεται ως `postgres` (`rolsuper`/`rolbypassrls` = true) με το όριο
«μόνο SELECT» γραμμένο **σε κείμενο του prompt** — ο ίδιος ο Grok το επισήμανε (`13 §Ισολογισμός`). **Ανοιχτό
ερώτημα:** αν ο Supabase connector του Grok δέχεται custom ρόλο και όχι μόνο service_role — **ΔΕΝ
ΕΠΑΛΗΘΕΥΤΗΚΕ** (`03 §Τι ΔΕΝ επαληθεύτηκε`). Δοκιμάζεται **πριν** στηριχτεί οτιδήποτε πάνω του.

**Επαλήθευση Κύματος 2:**
```sql
SELECT count(*) FILTER (WHERE req_id IS NOT NULL) AS me_req, count(*) AS synolo
  FROM audit_log WHERE created_at > now()-interval '1 hour';     -- me_req > 0 μετά το deploy
SELECT rolname, rolsuper, rolbypassrls FROM pg_roles WHERE rolname='tms_monitor';  -- false, false
```
**Τι γίνεται «επαληθευμένο»:** ότι κάθε εγγραφή φέρει αναγνωριστικό αιτήματος και ότι υπάρχει πραγματικό όριο
ανάγνωσης. **Μένει ανεπαλήθευτο**: ότι τα `console.log` του Worker φτάνουν όντως στα Workers Logs μετά το
`invocation_logs=false` — εκκρεμεί από το `08` και **απαιτεί κλειδί Cloudflare** που σήμερα δεν υπάρχει.
